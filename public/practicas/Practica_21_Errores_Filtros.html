Repaso flash · 5 min

3 conceptos clave

Iterator

Si un módulo te devuelve una lista (array), Iterator la "abre" y procesa cada ítem por separado. Como sacar caramelos de una bolsa, uno por uno.

Aggregator

Hace lo opuesto: junta varios items en uno solo (texto, array o JSON). Como meter todos los caramelos juntos en una bolsa nueva.

Error handler

Cuando un módulo falla (API caída, dato vacío, etc.), el escenario explota. El error handler te dice qué hacer en ese caso: reintentar, ignorar, alertar.

Ejercicio 1 · 20 min

Iterator: procesar una lista item por item

Vas a leer todos los emails de tus últimas 24 hs en Gmail, y por cada uno guardar el remitente y el asunto en una planilla. Sin Iterator, te lo guardaría todo junto en una sola fila — un desastre.

Flujo:

Gmail · Search Emails Iterator Sheets · Add Row
Tocá para ver pasos

1. Creá una planilla con columnas: Fecha, De, Asunto.

2. En Make, módulo 1: Gmail · Search Emails. Filter: query newer_than:1d. Max results: 20. Esto devuelve un array de mails.

3. Módulo 2: Flow Control · Iterator. Array: el campo "Array" del módulo Gmail (te aparece automáticamente). Hace que cada email se procese individualmente.

4. Módulo 3: Google Sheets · Add a Row. Mapeá: Fecha = {{2.date}}, De = {{2.from.address}}, Asunto = {{2.subject}} (los 2. apuntan al Iterator, no al Gmail original).

5. Run once. Tendrías que ver tantas filas nuevas como mails recibió.

Listo si: en la planilla aparecen N filas (1 por cada mail), no 1 fila con todo concatenado.

Ejercicio 2 · 25 min

Aggregator: del detalle al resumen

Ahora hacé lo opuesto: leé las filas de una planilla "Pendientes" y mandate un solo mensaje a Telegram con todas juntas, en formato lista.

Flujo:

Sheets · Search Rows Text aggregator Telegram · Send Message
Tocá para ver pasos

1. Planilla con columnas: Tarea, Prioridad. Cargá 5 filas.

2. Módulo 1: Google Sheets · Search Rows. Sin filter (devuelve todas). Max: 10.

3. Módulo 2: Tools · Text aggregator. Source = Google Sheets. Row separator = New row. Text:

• [{{Prioridad}}] {{Tarea}}

4. Módulo 3: Telegram · Send a Text Message. Mensaje:

📋 *Tus pendientes:*
{{2.text}}

5. Run once. Solo debe llegarte UN mensaje, con todas las tareas en una lista.

Listo si: recibís UN solo mensaje en Telegram, no 5 mensajes separados.

Ejercicio 3 · 25 min

Error handler: que tu flujo no se caiga

Tomá un escenario que ya tenés (de la clase 18 o 20) y agregale manejo de errores. El objetivo: si un módulo falla, en lugar de detenerse, el flujo te avise por Telegram y siga procesando los siguientes ítems.

Tocá para ver pasos

1. Abrí el escenario que querés robustecer (sugerencia: el de Práctica 18 con la API del dólar).

2. Hacé clic con botón derecho sobre el módulo que más probable falle (el HTTP del API). Elegí Add error handler.

3. Te aparece una ruta nueva, gris/punteada. Agregale un módulo Telegram · Send a Text Message con este mensaje:

⚠️ *Error en escenario*
Módulo: {{1.name}}
Mensaje: {{1.message}}
Hora: {{formatDate(now; "DD/MM HH:mm")}}

4. Después del Telegram, agregá un módulo Flow Control · Resume. Esto le dice a Make: "después del aviso, seguí con el siguiente ítem como si nada".

5. Para testear: temporalmente cambiá la URL del API a algo inválido (ej: https://dolarapi-falsa-xyz.com/v1/dolares), corré el escenario, deberías recibir el mensaje de error en Telegram.

3 tipos de error handlers principales:

  • Resume: avisa y sigue con el próximo ítem
  • Rollback: deshace todos los cambios de la operación que falló
  • Break: guarda el estado y permite reintento manual desde el panel

Listo si: al simular un error con URL falsa, te llega un mensaje al Telegram y el escenario no queda bloqueado.

Cierre

Antes de irte

  • De los escenarios que construiste hasta hoy, ¿a cuál le agregarías error handlers urgente?
  • ¿Qué procesos tuyos manejan listas (clientes, productos, órdenes) que podrías iterar?

Idea: "Robusto" no significa complicado. Significa que cuando falla algo, el negocio se entera y sigue funcionando. Esa es la diferencia entre un experimento y un sistema.

Nota Docente — Solo para el profesor

Esta es la práctica más técnica del curso. Es normal que el ejercicio 3 (error handler) cueste. Si se atrasan, prioridad: que entiendan el concepto del Iterator y Aggregator (ej. 1 y 2). El error handler se puede revisar luego en clase 22 cuando armen su proyecto final. Recordatorio: no hace falta que TODOS los módulos tengan error handler — solo los críticos (APIs externas, llamadas a IA pagas, envío a clientes).
