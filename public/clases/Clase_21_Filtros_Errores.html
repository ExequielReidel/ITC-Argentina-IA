Repaso · 10 min

¿Qué hicimos la clase pasada?

Construiste tu Empleado Digital: un flujo donde la IA clasifica los mensajes, devuelve JSON, y Make ramifica el flujo según la decisión. Es la integración más poderosa que vimos.

  • ¿Tu Empleado Digital clasificó bien todos los mensajes? ¿Hubo errores?
  • ¿Algún flujo se cortó esta semana sin que sepas por qué?

Lo que vamos a aprender hoy es lo que separa al hobbysta del profesional. Cualquiera puede armar un flujo. Pocos saben qué hacer cuando el flujo falla. Hoy vos vas a saber.

Desarrollo teórico · 20 min

Los 3 tipos de errores que vas a enfrentar

Error de conexión

La API externa no responde, internet se cae, el servidor está caído.

Solución: reintentos automáticos.

Error de datos

Llega un dato vacío, mal formateado, o que no esperabas (ej: email sin @).

Solución: validar con filtros.

Error de lógica

El flujo se ejecuta sin error pero el resultado es incorrecto (ej: dos veces el mismo mail).

Solución: revisar prompts y mapeos.

La regla de oro

Esperá lo mejor, programá para lo peor. Cuando un escenario corre 1.000 veces, alguno va a fallar. La pregunta no es "¿y si falla?" sino "¿qué pasa cuando falle?". Diseñá pensando en el fallo desde el día 1.

Filtros: el guardián entre módulos

Un filtro es una condición que el dato tiene que cumplir para pasar al siguiente módulo. Si no cumple, el flujo se detiene en ese ramal sin error.

Operadores lógicos en filtros de Make:

Equal el valor es exactamente igual
Not equal el valor NO es igual
Contains el texto contiene una palabra
Greater than el número es mayor que
Exists el campo no está vacío
Matches pattern cumple un patrón (regex)

También podés combinar condiciones con AND (todas se cumplen) y OR (al menos una se cumple). Ejemplo:

{{Email}} contains "@"
AND
{{Monto}} greater than 0

→ El flujo solo avanza si tiene email válido Y monto positivo.

Iteradores y Agregadores

Cuando un dato viene en lista (ej: 10 productos en un pedido), Make trata cada elemento por separado. Para eso existen:

Iterator

Toma una lista (ej: 10 productos) y la separa. El flujo se ejecuta una vez por cada elemento.

Útil: procesar carrito de compras producto por producto.

Aggregator

Lo opuesto: toma muchos datos individuales y los junta en una sola lista.

Útil: armar un mail con resumen de TODAS las ventas del día.

Manejo de errores en Make

Cualquier módulo en Make puede tener un "Error Handler" conectado. Hacés clic derecho sobre el módulo → "Add error handler". Aparece una rama gris alternativa que se ejecuta SOLO si ese módulo falla.

4 tipos de error handlers:

  • Resume: ignora el error y sigue con el siguiente módulo.
  • Rollback: deshace lo que hizo (avanzado).
  • Commit: guarda lo hecho hasta ahora y termina.
  • Break: espera y reintenta más tarde (ideal para errores temporales).

Práctica guiada · 40 min

Caso: heladería "El Polo Sur" en San Juan

Diego tiene una heladería que recibe pedidos por WhatsApp y por su web. Su flujo procesa entre 50 y 100 pedidos por día. Vamos a blindarlo: validar datos, manejar errores, procesar listas de productos y armar reportes diarios.

1

Validar datos con filtros antes de procesar

El primer pedido del día tenía email vacío y rompió el flujo. Vamos a evitar que pase de nuevo.

  • Hacé clic en la conexión entre el módulo Sheets y el siguiente módulo. Aparece una llave inglesa.
  • Click → "Set up filter".
  • Configurá: {{1.Email}} "Contains" "@" AND {{1.Telefono}} "Exists".
Ahora si llega un pedido con datos incompletos, el flujo se corta limpio sin tirar error.
2

Procesar lista de productos con Iterator

Cada pedido tiene varios productos. Diego necesita descontar el stock de cada uno por separado.

  • Si los productos vienen en un campo del form como "2 cucuruchos chocolate, 1 kg dulce de leche, 3 paletas frutilla", primero parseámoslos con IA.
  • Módulo OpenAI con prompt:

Convertí este pedido en JSON estructurado.

Pedido: "{{1.Pedido_texto}}"

Devolvé SOLO una lista en formato JSON:
[
  { "producto": "...", "cantidad": N },
  { "producto": "...", "cantidad": N }
]

  • Luego: módulo Iterator → array {{2.choices[].message.content}} parseado.
  • Después del Iterator, módulo Sheets → "Search Rows" para buscar el producto, y luego "Update Row" para descontar el stock.
3

Agregar manejo de errores al módulo OpenAI

A veces la API de OpenAI tiene picos de demora. No queremos perder pedidos.

  • Click derecho sobre el módulo OpenAI → "Add error handler".
  • Aparece una rama gris. Conectá un módulo "Break".
  • Configurá: 5 reintentos cada 5 minutos. Si después de eso sigue fallando, manda alerta a Telegram.
Ahora el flujo es resiliente: si falla, reintenta. Si igual falla, te avisa para que vos lo resuelvas manualmente.
4

Reporte diario con Aggregator

Segundo escenario para Diego: cada noche a las 22hs, juntar todos los pedidos del día y mandarle un resumen ejecutivo por mail.

  • Trigger: Schedule → todos los días 22:00.
  • Sheets → Search Rows: filtrar pedidos del día.
  • Aggregator (Text): juntar todas las filas en un solo bloque de texto.
  • OpenAI: pedirle un resumen ejecutivo.

Sos analista de la heladería El Polo Sur (San Juan).

Acá están los pedidos del día:
{{aggregator.text}}

Devolveme un reporte con:
1) Total de pedidos
2) Productos top 3 más vendidos
3) Horario pico de pedidos
4) Una observación útil o tendencia
Tono cercano, máximo 150 palabras.

  • Gmail → Send: mandar el resumen a Diego.

Buenas prácticas profesionales para tus escenarios

  • Nombrá tus escenarios con sentido: "[Heladería] Pedidos web → Stock + Reporte" no "Untitled scenario 12".
  • Renombrá cada módulo haciendo doble clic. "Validar email" en lugar de "Filter".
  • Agregá Notes en módulos clave para documentar la lógica.
  • Versioná: antes de un cambio grande, "Clone" el escenario y trabajá en la copia.
  • Revisá el History semanalmente. Si hay errores recurrentes, ajustá filtros o handlers.
  • Loggeá las decisiones de la IA en una hoja aparte. Si después la IA empieza a fallar, vas a tener historial para ajustar el prompt.

Ejercicio autónomo · 15 min

Blindá tus escenarios existentes

  1. Abrí uno de tus escenarios funcionando.
  2. Agregá al menos un filtro de validación antes del primer módulo crítico.
  3. Configurá 1 manejador de error en el módulo más importante.
  4. Renombrá los módulos con nombres descriptivos.
  5. Agregá Notes en al menos 3 módulos.
  6. Probá rompiéndolo a propósito (datos vacíos, mal formato) y verificá que reaccione bien.

Desafío extra: creá un escenario "Health Check" que cada lunes te mande un Telegram con el resumen de cuántos errores tuvieron tus escenarios la semana anterior.

  • Manejás iteradores y agregadores para procesar listas.
  • Configurás error handlers con reintentos y alertas.
  • Aplicás buenas prácticas profesionales: nombres, notes, versionado.
